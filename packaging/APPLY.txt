The English site, as a replayable patch series
==============================================

Why patches and not a push: this session's GitHub credentials get a 403
on arturkryzan/gravity-integration-site, so nothing here can reach it.
These patches carry the identical work; you apply them in your own clone
and push from there.

There are two folders. Apply ONE of them, not both.


Which one do I need?
--------------------
In your clone, run:

    git log --oneline -8

Look for "Translate the rest of the content: commercial, proof,
conversion".

  You have it        →  use  new/   (@@NNEW@@ patches — everything since)
  You don't have it  →  use  full/  (@@NFULL@@ patches — the whole English build)

Hashes will differ from mine; git am replays diffs, not hashes, so a
different hash for the same commit message is expected and harmless.

Until 0005 lands, the English pages build but carry noindex, stay out of
the sitemap, and the language switcher doesn't offer them. That is what
"draft" means here, and it is why 0005 is the commit that actually turns
the English site on.

0007 is the only one that changes a Polish page. /kalkulator/'s day-rate
slider now starts at "1500" rather than "1 500" — Polish doesn't group
four-digit numbers, so the calculator's own JS has always rendered 1500
the instant you touch the slider, and only the static label disagreed.
Both come from the same formatter now. The commit message has the
measurements.

0008 and 0010 both came out of the harness added in 0009, which walks
the packaged archive looking for Polish text left on English pages.

0011 puts the English site in euro — 0, 799 and 1,799 — and leaves the
Polish one on 2999 and 7999 PLN. One deliberate loose end rides along
with it, spelled out in its commit message: the Stripe Buy buttons still
point at the PLN checkouts until you set the euro prices up there.

0012 through 0016, and 0018, touch no page at all. They move the prose you are
reading — and the README inside the site archive — out of a scratch
directory and into the repo, alongside a script that assembles both of
these zips and refuses to ship a patch series that doesn't replay to the
tree it was tested on. Apply them or drop them; the site is identical
either way.

0017 removes /en/roi-calculator/ and leaves the Polish /kalkulator/
alone. It closes the second loose end 0011 left open — the English
calculator still quoting PLN — by taking the page away rather than
repricing it, because its sliders are scaled to Polish contractor day
rates and relabelling them in euro without rescaling them would have it
compute nonsense confidently.

Most of that patch is not the deletion. The English nav asks for each
item's URL, and a page missing from a locale deliberately falls back to
the Polish URL — right for a page awaiting translation, wrong for one
that will never exist in English. Left alone, deleting the page would
have pointed the English nav item at the Polish calculator instead of
removing it. So the codebase now tells those two cases apart, and asking
for a URL a locale doesn't offer raises an error rather than quietly
answering in Polish. The commit message has the whole reasoning,
including why the privacy policy is treated the opposite way. 0018 is
its entry in this file.

What you'll see: the English menu is Home / Download / Contact, with
Pricing still in the secondary menu as before, and the English home
page's "for business" block has one button instead of two.

0020 replaces the deploy run-book with one written against your actual
server rather than a generic Apache. 0021 loads the MailerLite pop-up
again — Polish pages only, and only after the visitor accepts the
consent banner, so the tag stays silent until then and withdrawal clears
it. 0022 and 0023 fix the header: the MENU/CLOSE label no longer slides
sideways when the menu opens, and the scrollbar gutter is reserved so
the page doesn't shift underneath it.

0024, 0025, 0026 and 0029 are four quality passes, each with its own
report in the repo root:

                    theming. Changes nothing but the audit harness
                    itself; the report is the deliverable.
  0025  harden    → clears every P1 accessibility finding. Focus rings
                    on the hamburger and the rest of the controls,
                    accessible names for the logo link and the five ROI

  0026  optimize  → OPTIMIZE.md. Total page weight across the 18 routes

                    was kept.
  0029  polish    → POLISH.md. The first pass aimed at the design
                    system rather than at defects. Six tokens the
                    system was missing, 32 hex literals that were

                    don't know, and one in the right unit on the wrong

0026 also moves 4.5 MB of files nothing references out of public/ and
into media-src/orphans/, and moves the originals of every re-encoded
image there too. Nothing on the site points at them; they are kept in
the repo so a future edit has the source to work from.

0029's visible cost is 26 pixels: capping the cookie panel's paragraph
at its real 68 characters wraps it onto a fifth line at desktop widths,
taking the bar from 154px to 180px. That was a deliberate trade rather
than an oversight — it is the one paragraph on the site the reader is
being asked to make a decision about. Below 1024px nothing moves at
all, because the column is already narrower than the cap. The commit
message and POLISH.md both carry the measurements.

0027 and 0028 change no code at all. 0027 is this file and the README

0028 corrects three claims about fonts in OPTIMIZE.md: a probe of the
actual network requests showed the Epilogue latin-ext subsets do NOT

0031 is the only patch here that changes what a visitor sees on both
locales at once, and it does two things.

The fullscreen menu listed four items in identical white, so the one the
whole site funnels toward — Pobieranie / Download — was styled as if it
were interchangeable with Kontakt. It now carries the brand green, and it
is the only item that does. Hover and keyboard focus invert it to white
rather than reusing the green, because leaving it green on hover would
have made the most important item the only one in the list with no
pointer feedback. Measured at 1440, 768 and 390: 3.22:1 for the green on
the menu's real painted ground, 5.09:1 for the white — the type is 36-64px,
so AA asks 3:1.

The second half adds a direct installer link to the download form's
success panel. By the time that panel renders the address is already in
MailerLite and the automation has fired, so waiting on an inbox buys
nothing; the e-mail stays the headline and this stays a link rather than
a button. Its click pushes a dataLayer `direct_download` event and
deliberately does not re-fire generate_lead for a person already counted.

  ONE THING TO DO ON THE SERVER: the link points at
  https://gravity-integration.com/downloads/GravityInstaller.exe
  and that file has to be there. Put the installer at that path before
  this goes live, or the panel will offer a 404 to exactly the people
  who were keenest to download.

0032 re-audits the whole site now that the four quality passes have
landed, and rewrites AUDIT.md. It changes no page: the report is the
deliverable, and the only code it adds is six more measuring harnesses.

The site scores 16 out of 20 against the same 18 routes and four
viewports that scored 12 before, with no P1 findings for the first time.
Of the previous report's 19 findings, 12 verify fixed, 2 are better but
not finished, and 5 are still open. Every one was re-measured rather than
assumed closed — for one of them the old selector no longer matched
anything, which is not the same thing as the problem being gone, so the
element was found by its text and measured directly.

Eleven findings remain, none of them urgent: seven 17px links in the
contact block, the ROI sliders' focus ring two hundredths short of the
contrast floor, the header's navigation marked up as a <section> rather
than a <nav>, eleven images still shipping larger than they are drawn,
and the tail end of the colour-token migration.

The part worth reading in AUDIT.md is not the score. All thirteen
findings the automated sweep produced were false — every one of them a
case of a probe reporting the absence of something it simply cannot see.
The focus ring on the calculator sliders is drawn on a pseudo-element
that no DOM query can reach, so eleven controls that visibly light up
under a real Tab were reported as having no indicator at all. Chasing
down why one of those "passes" made no sense is what turned up the only
genuinely new problem in the whole audit. Had the sweep been believed,
the report would have listed eleven things that aren't wrong and missed
the one that is.

To apply and push
-----------------
    git status                      # must be clean before git am
    git am /path/to/new/*.patch     # or full/*.patch
    git push

If git am stops on a patch you already have, `git am --skip` steps over
it. To back out entirely at any point: `git am --abort`.


One expected warning
--------------------
git reports "trailing whitespace" once, in Footer.astro. That is
deliberate — the tab indentation is load-bearing in the rendered output.
Apply it as-is; don't let an editor strip it.


Verified before packaging
-------------------------
Both series were replayed into fresh clones from their respective base
commits. Each produced tree @@TREE@@,
identical to the branch head here — so what you apply is what I built and
tested, not a reconstruction of it.
